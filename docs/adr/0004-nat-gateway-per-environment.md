# 0004. NAT Gateway は dev で単一、prod で AZ ごと

状態: Accepted

## 背景
NAT Gateway は最もコストが大きい項目の一つ（1台約 $45/月）。AZ ごとに置くと AZ 障害に強いが、台数分のコストがかかる。

## 決定
- 変数 `single_nat_gateway` で切り替える。dev は `true`（1台に集約）、prod は `false`（AZ ごとに配置）。
- プライベートルートテーブルは AZ ごとに作り、冗長構成では同一 AZ の NAT へ向ける。
- S3 ゲートウェイエンドポイント（無料）を常に有効にし、ECR レイヤ取得の NAT 通信料を削減する。

## 理由
- dev は可用性よりコストを優先し、prod は AZ 障害時にも外向き通信を維持する。
- 差分は tfvars の1変数で表現でき、モジュールの構造は共通のままになる。

## トレードオフ
- dev で NAT の AZ が落ちると外向き通信が止まる（検証環境のため許容）。
- 単一 NAT では AZ 間通信料が発生する。
- 試算は [docs/cost.md](../cost.md)。
